# Administrator CRUD Coverage

Status: final implementation and verification matrix.

This matrix covers all 47 registered Filament resources and all seven
registered custom administrator pages. A `Deferred with documented reason`
row is deliberately not counted as complete: the list/detail experience is
available and secured, but one or more state-changing operations still require
the owning module's API or application workflow.

reverse, or a compensating transaction—not hard deletion.

## Deferred work register

The 22 deferred rows fall into five bounded, testable follow-up slices:

1. **Asset and location hierarchy:** charging-station/site retirement plus
   station → EVSE → connector and operating-hours authoring.
2. **Procurement and inventory workstations:** purchase documents, goods
   receipt, counts, adjustments, and transfers with maker-checker separation.
3. **Maintenance and support workflows:** incident/plan/work-order/ticket
   authoring, assignment, evidence, parts, and state-specific forms.
4. **Financial and charging review workflows:** finance review, session review,
   settlement preparation/approval, and tariff publication/retirement.
5. **Identity administration:** invitation, membership scope/role assignment,
   and safe user-profile changes.

These are missing administrator interaction surfaces, not missing domain
guards. Their existing APIs and application services remain the authoritative
mutation boundaries. Implementing generic Filament edit/delete actions in
their place would bypass state machines, idempotency, immutable history, or
separation-of-duty controls.
