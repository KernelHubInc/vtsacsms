# ADR 0018: Private KYC deployments and explicit review policy

Status: Accepted for deployment tooling and review policy. Unattended self-hosted assurance remains incomplete.

Follow-up: [ADR 0019](0019-optical-kyc-and-live-capture.md) supersedes the assurance requirement and unresolved VPS3 route below following the owner's explicit optical-verification choice and confirmation of private database access. The original decision is retained for history.

Extends [ADR 0017](0017-isolate-kyc-evidence-processing.md). The requested topology runs one production KYC stack on VPS2 and a separate staging stack on VPS3. Both production Laravel app nodes use the production KYC stack. Staging Laravel uses staging KYC. Mobile builds select only the corresponding Laravel API; they receive no KYC service credentials or internal addresses.

Each KYC stack has an API, Celery worker, beat scheduler, and dedicated ephemeral Redis. Durable processing and outbox records use a dedicated environment-specific PostgreSQL database/role on VPS4. Encrypted evidence uses distinct private buckets and credentials on self-hosted S3-compatible storage. Only a TLS ingress is published, bound to an assigned RFC1918/VPN interface and restricted by source address. The API and Redis publish no ports. The public load balancer must have no KYC processor upstream. TLS and directional signatures remain mandatory.

Identity owns `kyc_settings`, permission `identity.kyc.settings.manage`, and the `review_mode` snapshot on each verification. Manual is the default. Policy changes are authorized, tenant scoped and audited, and apply only to new attempts. In manual mode, processor approvals/rejections enter `NEEDS_REVIEW`. In automatic mode, approval additionally requires the deployment readiness switch, retained evidence and passed OCR, document authenticity, face matching and liveness checks. Missing/failed checks never approve. The readiness switch can stop future automatic approvals for already queued attempts. Human decisions remain authoritative over later callbacks.

The initial self-hosted adapter performs Tesseract extraction, conservative text consistency checks, and OpenCV YuNet/SFace one-to-one face comparison using checksum-pinned local models and explicitly calibrated thresholds. Face features exist only in processing memory, are cleared after comparison, and are never returned, logged or stored as templates. No identity data is sent to a third-party assurance provider. `document_data` is distinct from document authenticity. A still selfie is not a liveness challenge. The adapter deliberately returns unavailable document authenticity and liveness, so it cannot approve unattended.

National ID, Philippine driver's license and passport submissions are supported by the workflow. Automatic authenticity for all three is **not implemented**. It requires trusted issuer verification material/document specifications (for example PSA-signed QR verification with trusted, rotated issuer keys), and a tested liveness capture/PAD pipeline. Passport MRZ checksums or matching OCR fields alone are insufficient. Production acceptance must include consenting evaluation data, false-match/false-non-match and spoof testing, model provenance, document coverage, and device capture/replay tests. These cannot be replaced by unit tests or arbitrary thresholds.

Operational consequences: the production KYC node is a single processing failure domain; Laravel fails safely and pending work resumes after recovery. Staging is never a production failover. VPS3 requires a private route/firewall authorization to VPS4 for its databases. The stated firewall allowing only VPS1/VPS2 is an unresolved deployment blocker, not a reason to publish PostgreSQL. Additive core migrations, processor migrations, storage policies and backups are deployed separately; rollback preserves evidence, policy history and outboxes.
