# ADR 0019: Optical KYC and a self-hosted live camera challenge

Status: Accepted implementation; production acceptance remains a deployment gate.

The owner chose **optical ID checks + face matching + liveness**, with all processing self-hosted, and confirmed that VPS3 already has private access to VPS4. This supersedes the unresolved assurance choice and database-route blocker recorded in ADR 0018. No public database access or firewall change is needed. Actual private addresses and credentials remain operator-supplied.

Identity snapshots an `assurance_profile` on each attempt. New attempts use `optical_v1`; existing rows retain `issuer_v1`. Neither a settings change nor a later callback can lower an existing attempt's requirements. Manual/automatic review remains a separate, audited tenant policy. The deployment readiness switch remains off until evaluation and operational acceptance are complete.

`optical_v1` requires passed OCR, optical document structure, personal-data consistency, document-to-selfie face comparison and a completed live challenge. `document` continues to mean issuer authenticity and remains unavailable in this adapter. A separate `optical_document` check prevents a text match from being represented as government authentication. The parser supports Philippine National ID/PhilSys, Philippine driver's license, and Philippine TD3 passport text profiles. Passport MRZ check digits are consistency checks only. Unknown layouts, foreign issuers, unreadable/ambiguous fields, mismatches and multi-portrait documents do not automatically pass.

Flutter obtains camera prompts through authenticated Laravel endpoints. Laravel supplies the tenant/subject scope and signs its private processor requests; mobile never receives an internal URL or service secret. The processor issues opaque single-use tokens for nine stages: center, four randomly selected left/right turns, and a return to center after each turn. Only the next action is revealed. Each stage requires two distinct accepted frames separated by server-observed time. A session lasts at most 120 seconds, each stage at most 20 seconds, and at most 80 frames are evaluated. Exact retries return the prior acknowledgement; stale tokens, repeated normalized frames, cancellation, expiry and concurrent replacement cannot advance the session.

YuNet identifies one sufficiently large face. SFace checks continuity against the reference selfie. A checksum-pinned `anti-spoof-mn3` ONNX model evaluates presentation attacks locally; its original RGB normalization and real/spoof output order follow the upstream Open Model Zoo model documentation. Head-turn evidence uses the nose position relative to the detected eye line, with separate evaluated center/turn bands. This geometry is not a calibrated angle estimate. Face and PAD thresholds have no production defaults. Inconclusive frames never advance; failed PAD or continuity terminates the challenge.

Only the first accepted center frame is stored, encrypted, as the reference selfie. Other frames are processed in memory; no face embeddings are persisted. Encrypted challenge state contains scoped tokens, frame hashes, counters and the reference key. Abandoned captures expire after two minutes; a completed challenge must be submitted within ten minutes. The existing beat process removes expired references and retries failed deletes. A crash between object storage and database commit can leave an orphan until the existing bucket lifecycle/retention sweep; storage failures cannot claim completed erasure. Submitted references follow the existing evidence retention/consent withdrawal policy. Challenge state is erased after processing. Core callbacks carry check codes only.

This implementation does not establish government issuance, tamper-proof hardware capture, certified PAD, resistance to arbitrary deepfakes/virtual cameras, or measured biometric accuracy. Before automatic production approval: use consented representative evaluation data, measure false acceptance/rejection and printed-image/screen/video attacks, test the supported phones and camera orientation/mirroring, assess accessibility/fallback needs, and set reviewed thresholds. A model loading test and synthetic protocol tests cannot establish those properties. Manual policy remains available and inconclusive final results go to authorized review.

Rollout: migrate/upgrade every Laravel node and keep `KYC_ASSURANCE_PROFILE=issuer_v1` during the mixed-version phase; upgrade the processor and apply Alembic 0002; install/test face and PAD models; release the updated mobile application; then select `optical_v1` for new attempts. Old mobile clients receive `LIVE_CAPTURE_REQUIRED` if they try a still selfie for an optical attempt. Stage the new mobile version before exposing optical attempts. Keep automatic approval off until acceptance. Roll forward preserves both policy columns and evidence.
